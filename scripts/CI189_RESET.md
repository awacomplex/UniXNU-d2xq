# CI189: one armed Samsung Download reset through PS_HOLD

CI188 reached a verified `P2 old=00 new=2a got=2a` and `R0 R1`. The user then
reported repeated reboots and manually entered Download to end that test.
That establishes a successful PON-byte write/readback and observed reboots;
it does not establish an automatic Download landing or identify every reset.
The durable data state remains repair counter 7, next repair slot 2.

CI189 tests the normal same-device Samsung reset path rather than enabling
the APSS watchdog. It is a hardware-changing reset-only build, not read-only.
It must never ingest repair slot 2 or write userdata, misc, or repair progress.

## Entry and one attempt

The outer `ci189-reset-probe.inc` owns full trusted-counter validation and the
RECOVERY ARM-record protocol. It must durably consume and read back the complete
ARM record before defining `bool ci189ArmConsumed = true` and expanding
`ci189-reset-hardware.inc`. The hardware include independently requires that
flag, `repairCounter`, counter 7, and nextRepairSlot 2. No hardware path returns
to metadata/ingest. The consumed record, not a PMIC reason or an undocumented
scratch bit, prevents a repeated attempt on a subsequent boot. Refer to the
outer probe/record specification for its exact bytes and storage checks.

The arming record is exactly 4096 bytes generated by `ci189-prepare-reset.py`
from `ci189-reset-arm.json`. Its SHA256 is
`c3a64911c1a23ddba3a0a36e8d3e31d799f6b0aaa89a4586c54004acf3e866ea`.
It binds this build's nonce, image SHA, counter 7, repair slot 2 and fixed
geometry. The kernel hashes the entire block, accepts only that compiled-in
digest, writes one all-zero CONSUMED block, issues SYNCHRONIZE CACHE and checks
all 4096 read-back bytes. No reset-specific MMIO or SCM precedes that check.
Any missing, old, corrupt, torn or already consumed record stops without a
consume write or reset attempt. Failures while consuming stop before reset.
Consumption is intentionally not rolled back if later hardware checks fail.

The sole diagnostic disk write is LUN0 WRITE(10), one block at fixed LBA
`0x24f13` (151315). This is the RECOVERY start previously measured in the
phone's GPT/PIT and used successfully for repair slots 0 and 1; the measured
partition ends at 171519. CI189 relies on that established fixed mapping and
does not re-prove the GPT partition name at runtime. It retains the complete
existing trusted userdata-counter and geometry checks. It neither changes
the general hostWrite4k authorization nor accepts a record-provided address.
The obsolete source block in RECOVERY is disposable; the next authorized
repair payload will replace it. This does not rewrite repair slots 0 or 1 in
userdata. A host must deliberately re-upload an ARM record to permit another
attempt: the guarantee is at most one attempt per installed ARM record, not
an irreversible ban on further user-authorized tests.

The hardware include contains no disk operation. A failure after a hardware
write can leave the changed configuration in place; there is no rollback,
automatic retry, watchdog reset, or alternate guessed address/function ID.

## Hardware sequence

All register values/addresses in this section are hexadecimal unless marked
decimal. The raw counter helper is the CI187 real-device-tested algorithm:
19,200,000 Hz only, at least 21 ticks per microdelay, at most 4096 rounds,
rejecting reversal/wrap and frozen/exhausted delays. `Q0/Q1` unconditionally
self-test it. CI189 also checks every raw-counter sample against the previous
sample across all helper/SMC/wait invocations. `CurrentEL` must equal 4 (EL1),
printed with frequency, before SMC.

Retain maps for SPMI core `0c440000/1100`, configuration `0c40a000/1000`, the
selected observer/RW pages, IMEM `146bf000/1000`, and PS_HOLD `0c264000/1000`.
SPMI version must be in `[50000000,60000000)`. Scan all 512 entries, choose the
last PPID `008` with owner EE0, preserving valid APID0/duplicate handling.
Require Gen2 PON subtype 04 or 05 at SID0 address 0805. Recheck full selected
entry, owner and version before every transaction. One-byte observer READL
uses `08000000 | ((address & ff) << 4)`; WRITEL uses `(address & ff) << 4`.
Only 085a, 085b and 088f may be written. Poll at most 1000 times and require
DONE without error bits. Verify every entire written byte through observer.

After all required SCM availability checks, perform this normal-path order:

1. `C0/C1`: clear secure DLOAD with BOOT command10, value arguments `(0,0)`;
   clear IMEM restart reason to zero and read back, matching the SEC normal
   setter. Do not enable Qualcomm crash/EDL DLOAD.
2. `H0/H1`: SID0 PS_HOLD_RST_CTL2 at 085b, clear bit80 and verify; run 500
   bounded raw microdelays (at least 500 microseconds, with cross-call monotonic
   checks); at 085a preserve high nibble and set low nibble to 07 (hard reset);
   re-read 085b, require enable still clear, preserve other bits, set bit80.
   This follows same-device QPNP setup with no audited secondary/override.
3. `I0/I1`: write/read back generic normal reboot magic `77665501` at
   `146bf65c`, as msm_restart_prepare does for `"download"`.
4. `P1/P2`: read SID0 088f, preserve bit0 and store `(old & 1) | 2a`, the
   Gen2 encoding of Samsung Download reason15. Verify the complete byte.
   Recheck both reset-control bytes, reason byte and IMEM before shutdown.
5. `D0/D1`: disable secure debug image using BOOT command09, arguments `(1,0)`.
6. `B0/B1`: halt the SPMI PMIC arbiter using PWR command01, argument `(0)`.
   There is no SPMI access or PMIC rollback after this point.
7. `R0`: if the PWR command02 availability query was positive, request secure
   PS_HOLD deassertion with argument `(0)`. Any returned error terminates.
   If explicitly unavailable, or if a supported call returns success without
   resetting, `R1 X0` precedes the same-source direct write of zero to
   `0c264000`. This is the documented deassert_ps_hold fall-through, not a
   fallback from an SCM error. `X1` means that direct write returned.

If direct PS_HOLD returned, use only raw counters and bounded microdelays to
wait up to ten actual counter seconds / ten million iterations, then panic.
Never read PS_HOLD or query the halted SPMI bus to explain a failed reset.
There is no IODelay, PSCI, HVC, scheduler wait, or WDT configuration/enable.

## Exact SCM transport and refusal rules

Function base is `02000000 | (service << 8) | command`; atomic adds `80000000`,
SMC64 adds `40000000`. Arginfo for one/two value arguments is 1/2, passed in
x1; arguments start at x2. x4/x5 and x6 initially zero. Returned status is signed
low32(x0); x1-x3 carry service return values. The bounded wrapper stores all
x0-x6 outputs in ordinary state before any C helper, timer or log call.

Discover the same-source ABI with atomic INFO self-availability:
first `x0=c2000601, x1=1, x2=82000601`, remaining inputs zero. Only a completed
nonzero status or zero ret1 permits the source's SMC32 variant
`w0=82000601, w1=1, w2=82000601`. An interrupted/exhausted or counter-failed
session panics rather than falling through to the other ABI. SMC32 inputs and
outputs are low32 values. Both supported source variants execute `smc #0`.

For subsequent availability use the source's non-atomic INFO command
`42000601` (64) or `02000601` (32), arginfo1, queried *base* FNID in arg0.
Interpret ret1 as signed low32, matching scm_is_call_available's `int` return.
DLOAD `02000110`, SDI `02000109`, and arbiter `02000901` must all be positive
before state-changing calls. PS_HOLD `02000902` may be zero for the documented
direct branch. Negative values, any transport error or unknown positive
transport status terminate. No IO-write/TCSR or different function-ID fallback
is attempted when a required call is unavailable.

Actual calls are atomic with the selected ABI: BOOT10 `(0,0)`, BOOT09 `(1,0)`,
PWR01 `(0)`, PWR02 `(0)`. `SCM_INTERRUPTED=1` resumes with all returned x0-x6
values, without replacing function/argument registers. Stop at 128 calls or
ten raw-counter seconds; never retry busy -12/-55. The inline-assembly clobber
set conservatively includes the union of both same-source RKP configurations
(x7-x17, x19-x20), plus cc/memory, and does not touch Darwin's reserved x18.

Bounds cannot interrupt an SMC or MMIO/system-register access that never
returns, nor establish physical time if firmware changes the counter. Every
returned failure is terminal and the already consumed ARM record prevents
this build from automatically trying again after reboot.

## Reading the result

`S0 tag` is printed before each firmware call; `S1 tag status=... ret=...`
records its returned status. `A2` identifies the selected ABI. `H1`, `I1` and
`P2` establish their checked configurations, not a reset destination. A new
host-observed Samsung Download enumeration after the attempt is required to
claim success. Screen output uses the existing two-row ring and may retain
old suffixes; identify the newest CI189 phase and complete panic message.

Validation and real-device outcome must be recorded by the build/flash owner.
This source alone does not prove that the phone will enter Download.
